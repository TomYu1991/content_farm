# Implementation Plan: content-pipeline-skeleton

## Overview

以 Python 3.11+ 的纯生成逻辑与 Astro/TypeScript 静态站点组成最小闭环：手动触发生成仅创建可审阅的 Markdown 草稿；人工完成五项审阅、将 `draft` 改为 `false` 并合并后，才由默认分支的静态部署发布。Markdown 是唯一手写文章内容，HTML 仅由 Astro 构建期生成。

## Tasks

- [x] 1. 建立 Python 与 Astro 静态项目基础
  - [x] 1.1 初始化 Astro 的 TypeScript 静态输出配置、Python 3.11+ 包结构、锁定依赖与测试命令
    - 配置站点绝对 HTTPS URL、静态构建输出、Python 测试与 TypeScript 测试脚本；仅纳入 Astro、内容/RSS/sitemap 所需组件、Hypothesis、fast-check 和 HTTP mock 测试依赖。
    - 不引入数据库、Redis、VPS、Docker、Ollama、Prefect、队列、动态后端或第二份手写 HTML。
    - _需求：1.1、1.4–1.6、2.1、6.12、8.8、9.8_
  - [ ]* 1.2 为基础配置编写可重复构建与测试命令的冒烟测试

## Notes

- 标有 `*` 的测试子任务为可选项，可在 MVP 加速时跳过；其余任务是实现闭环所必需的任务。
- 任务按增量方式组织：先建立静态内容与纯逻辑，再接入受限生成、审阅闸门和默认分支部署；不会留下未接线的组件。下方依赖图中同一 wave 的叶子任务标记为**可并行**，不同 wave 必须按顺序完成。
- 本阶段明确不实现数据库、Redis、Postgres、pgvector、Prefect、任务队列、VPS、Docker、Ollama、动态后端、登录、评论、CMS、支付、管理后台、第二份手写 HTML、Selenium、humanizer、AI 检测规避、自动跨平台发布或 KDP 自动化。
- 以下均为延后事项，**不是本 MVP 的任务**：仅在人工确认审阅能力稳定并显式启用时评估每周定时生成；上线后需要选题/反馈表单时评估 Tally；已有发布内容和真实访问、需要阅读/外链分析时评估 PostHog；有合法订阅者及确认订阅流程时评估 Resend；需要公开写接口时评估 Cloudflare Worker + Turnstile；需要持久化表单、订阅者或用户数据时评估 D1 或 Supabase（二选一）；公开 API 出现滥用或需要限流时评估 Upstash Redis；出现动态后端或复杂客户端故障且需要观测时评估 Sentry。
